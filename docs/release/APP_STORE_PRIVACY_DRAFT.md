# Blumi iOS App Privacy working draft

Status: **NOT SUBMITTED / NOT APPROVED**. Prepared 2026-09-28 from the current checkout, not from a signed release binary or live provider telemetry. This is a review aid for App Store Connect, not legal advice and not a completed privacy label. Apple requires a reachable privacy-policy URL and answers that cover the app and integrated third-party SDKs; each answer must describe the exact version submitted. See [Manage app privacy](https://developer.apple.com/help/app-store-connect/manage-app-information/manage-app-privacy/) and [App privacy details](https://developer.apple.com/app-store/app-privacy-details/).

## Checkout trace: location and matching fields (2026-09-28)

- The current mobile profile editor has no location input or OS location request, and no `expo-location` dependency or location permission declaration was found.
- **Implemented in this checkout, not deployed:** profile creation/update writes force the legacy coordinate columns to NULL; PostgreSQL hydration and account export no longer read or return those values. The columns remain for compatibility. Tests cover null writes and omission from reads/exports.
- **Staging evidence only:** a read-only count in the confirmed test/staging Supabase database found 0 accounts with either coordinate populated, so no staging data was changed. Production database identity/count are not confirmed and no production cleanup ran. Existing backup/restore evidence predates this check; production historical-storage and backup-retention questions remain OPEN. Do not make a final location declaration until the exact deployed backend/binary, all production databases, and backup behavior are verified.
- Apple's current App Privacy definition calls latitude/longitude with three or more decimal places “Precise Location.” Apple also explicitly maps non-SMS private in-app messages to “Emails or Text Messages” and generic free-form text fields to “Other User Content.” See [Apple's App Privacy details](https://developer.apple.com/app-store/app-privacy-details/) and [Manage app privacy](https://developer.apple.com/help/app-store-connect/manage-app-information/manage-app-privacy/).
- The profile stores a chosen identity-gender field, and discovery settings store selected genders. Both are linked to the account and used by matching. No sexual-orientation field is explicitly named, but the combination may reveal a sensitive preference. Keep **Sensitive Info** as a conservative candidate (linked / App Functionality) for human privacy/legal review; do not treat this working draft as the final declaration.

## Items not to invent

- Do not select “No, we do not collect data from this app.” Phone/auth, user IDs and durable messages make that false.
- Do not declare Photos/Videos, Contacts, payment-card data or Advertising Data just because an Apple category exists. Conversely, don't omit a category merely because a feature is optional or consent-based.
- App Review screenshots, privacy answers, and hosted legal copy must match the same signed build and enabled backend features. The local in-app legal draft now marks LiveKit audio and RevenueCat purchases unavailable in the first version, but the hosted pages are not live and the exact native binary/provider behavior remains unverified.
- App Privacy declarations include third-party SDK behavior. A source review and tests are supporting evidence; native privacy manifests, build settings, real-device traffic and provider documentation remain OPEN.
- No app `PrivacyInfo.xcprivacy` is tracked in source. The ignored, locally generated `apps/mobile/ios/Blumi/PrivacyInfo.xcprivacy` does exist and currently declares an empty collected-data array; that local file does not prove a clean EAS build contains the same manifest or that its declarations match the signed binary and SDKs. App Store Connect privacy labels and native privacy manifests are separate evidence; inspect the exact archive and privacy report before finalizing either declaration.
- Source account deletion removes the user's chat threads, and the chat schema cascades thread deletion to messages. This is code evidence only; environment deletion, Firebase completion, backups/retention and real post-delete behavior remain OPEN.
