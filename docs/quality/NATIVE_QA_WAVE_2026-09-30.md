## 1. How to run

1. Pull `claude/busy-cray-dl5wvr` into a separate folder (not the daily checkout).
2. `npm ci`
3. `npm run build:packages`
4. Start Metro with a cleared cache (image paths changed in this wave): `npm --workspace @blumi/mobile run start:clear`
5. Open the installed development client on the Simulator or iPhone and connect it to that Metro (same LAN for the iPhone).
6. Deep-link commands on the Simulator: `xcrun simctl openurl booted <url>` (scheme `blumi`, bundle `com.blumi.mobile`).

## 2. Conventions

- Status legend: **NOT RUN** / **PASS** / **FAIL** / **BLOCKED**. All items below start NOT RUN.
- Priority: **P0** critical flow (sign-in/register; Discover -> match -> chat -> room invite -> MiniRoom; realtime reconnect; notifications and deep links), **P1** important, **P2** polish.
- Platform: **Sim** = Simulator, **Phone** = physical iPhone, **Both**. Keyboard, airplane mode, push permission and VoiceOver feel are Phone-primary; layout checks are Sim-primary (iPhone SE, 13 mini and a large phone).
- Backend group:
  - **A**: mobile-only behaviour, runnable now against the deployed staging backend (Railway, `main` @ `2a55475` + `BLUMI_TRUST_PROXY`).
  - **B**: runnable only after migration 068 is applied and this branch's server is deployed (moderation 403 on profile writes, persona policy, server-side legacy lobby rejection, request validation, realtime auth cache/revocation, session reuse detection + 90-day cap + Firebase uid binding, N+1 fixes, repository parity, slow-consumer/fanout limits, `realtime.error` events). Mobile behaviour that depends on those responses is in B.
- Variants, defined once and referenced by "Variants: ..." in items:
  - **TR / EN**: run with device language Turkish (tr-TR) and English (en-GB). Copy, dates and placeholders match the locale, no truncation, no raw key strings (raw keys = FAIL).
  - **Large text**: Settings > Display > Larger Text at maximum (and accessibility sizes). Nothing clipped or unreachable; primary actions reachable by scrolling.
  - **VoiceOver**: every control has a label; state (checked, disabled, busy) is announced; hidden layers are not focusable.
  - **Reduce Motion**: Settings > Accessibility > Motion > Reduce Motion on. No looping or decorative motion, no scale/confetti/pulse; functional state changes remain visible.
- Evidence: path to screenshot/video, or a short note. A blank image where art is expected means a broken asset path (FAIL).
- Two accounts (two devices where possible) are needed for match, chat and room items. "Demo" means the built-in demo session.

## 4. Not verifiable here

This plan and its Simulator/iPhone runs do not prove:

- Performance: frame rate under load, cold-start time, memory. Needs profiling on physical devices.
- Battery and thermal behaviour; push delivery reliability at scale.
- Server behaviour under real load (slow-consumer and fanout limits); B items check client reaction only.
- Physical-device coverage beyond the owner's single iPhone (other models, older iOS, poor cellular).
- App Store / TestFlight readiness (separate gate in `docs/release/`).
- Visual approval of artwork: only the owner can give it.

Passing this plan means "Native verified" for the listed items only, not "Production ready".
